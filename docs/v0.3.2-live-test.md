# v0.3.2 实机回归测试清单

v0.3.2 将 manifest 工具从 Command-Line Tools 的 `apkanalyzer` 改为 Build Tools
自带的 `aapt2`。测试主机只需一套官方 Android SDK Build Tools 26.0.2 或更新版本，
同时使用其中的 `apksigner` 与 `aapt2`；不再需要 Command-Line Tools。

## 环境与升级

- [ ] 记录 AstrBot、NapCat、QQ、Java 与 Android SDK Build Tools 版本。
- [ ] 确认 `apksigner`、`aapt2` 来自同一套官方 Build Tools。
- [ ] 升级插件后版本显示 `0.3.2`，旧状态与 VERIFIED 文件仍在。
- [ ] 删除旧 `apkanalyzer_path` 配置（若有），确认 `aapt2_path` 留空可自动发现；
  若不能自动发现，再显式填写 `aapt2` 路径。

## Known-good APK

- [ ] 对已人工确认来源的 C 版 APK 执行：
  `python scripts/inspect_trusted_apk.py "D:\path\known-good-arcaea.apk"`。
- [ ] 输出 `Cryptographic signature: VALID`。
- [ ] package、versionName、versionCode 与已知信息一致，所有 signer SHA-256 可解析。
- [ ] 配置可信 signer 与 package 后，`/apull status` 不显示
  `TRUST_NOT_CONFIGURED` 或 `VERIFIER_UNAVAILABLE`。

## 正常流程

- [ ] `/apull check` 能读取官网版本；维护期间失败应明确返回且不产生分发。
- [ ] `/apull download` 完成后仍为 UNVERIFIED，未向群发送 APK。
- [ ] `/apull verify` 返回 VERIFIED，结果中的 package、versionName、versionCode、
  signer SHA-256 与文件 SHA-256 正确。
- [ ] `/apull flash_test` 能向白名单测试群发送小探针。
- [ ] `/apull distribute` 只分发 VERIFIED APK；再次执行显示 skipped，不重复发送。
- [ ] 重启 AstrBot 后 VERIFIED 与分发幂等状态仍有效。

## Fail-closed 回归

- [ ] 将 `apksigner_path` 指向不存在的文件：VERIFIER_UNAVAILABLE，不分发。
- [ ] 将 `aapt2_path` 指向不存在的文件：VERIFIER_UNAVAILABLE，不分发。
- [ ] 修改 APK 任意字节：验证失败，不分发。
- [ ] 使用未知 signer、不同 package 或不匹配 versionName 的测试 APK：分别阻断。
- [ ] 模拟降低完整 versionCode（含 versionCodeMajor）：ROLLBACK_DETECTED。
- [ ] 清空可信 signer：SECURITY_HOLD，历史 VERIFIED 也不分发。
- [ ] 验证失败文件不会通过普通群文件方式回退发送。
