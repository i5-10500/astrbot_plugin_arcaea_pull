# v0.3.1 实机真实性验证与闪传清单

单元测试不包含真实 Arcaea APK，也不能替代部署机器上的 Android SDK、NapCat、QQ
和 known-good 信任初始化。测试时不要运行任何来源未知 APK。

## 环境记录

- [ ] 记录 AstrBot、NapCat、QQ 客户端、Android Build Tools 和 Command-Line
  Tools 版本。
- [ ] 记录 `apksigner`、`apkanalyzer` 路径和 aiocqhttp 平台 ID（不提交凭据）。
- [ ] 备份 `state.json`；只把专用测试群加入 `flash_transfer_targets`。

## 信任初始化

- [ ] 使用用户已人工确认、曾实际安装或使用的 C 版 APK；不要使用本轮网络下载物。
- [ ] 执行
  `python scripts/inspect_trusted_apk.py "D:\path\known-good-arcaea.apk"`。
- [ ] 输出为 `Cryptographic signature: VALID`；记录 package 和所有 signer SHA-256。
- [ ] 将指纹和 package 分别填入 `trusted_signer_sha256`、
  `trusted_package_name`，重载插件。
- [ ] `/apull status` 不再显示 `TRUST_NOT_CONFIGURED` 或
  `VERIFIER_UNAVAILABLE`。

## 正常流程

- [ ] `/apull flash_test` 向白名单测试群发送小探针。
- [ ] `/apull download` 后状态为 UNVERIFIED，且尚未向群发送 APK。
- [ ] `/apull verify` 返回 VERIFIED，并显示精确 package、versionName、
  versionCode、signer SHA-256 和文件 SHA-256。
- [ ] VERIFIED 文件位于 `downloads/verified/`。
- [ ] `/apull distribute` 后白名单群收到真实 QQ 闪传 APK。
- [ ] 再次分发显示 skipped，群内不重复收到。
- [ ] 重启插件后 VERIFIED 和 distribution 状态仍有效。
- [ ] 从未收到聊天消息时，由 scheduler 完成检查、验证和分发。
- [ ] 模拟一个群失败后，下一轮只补发失败群。

## Fail-closed 安全用例

- [ ] 备份测试 APK 后修改任意字节；`/apull verify` BLOCK，绝不闪传。
- [ ] 使用另一个自己签名的测试 APK；signer pinning BLOCK。
- [ ] 使用 package 不同的签名测试 APK；package mismatch BLOCK。
- [ ] 使用 versionName 与 API 不同的签名测试 APK；version mismatch BLOCK。
- [ ] 用合成/测试状态模拟更低 versionCode；rollback BLOCK。
- [ ] 清空 `trusted_signer_sha256`；状态为 SECURITY_HOLD，历史 VERIFIED 也不分发。
- [ ] 故意配置不存在的 `apksigner_path`；状态为 VERIFIER_UNAVAILABLE，不分发。
- [ ] 故意配置不存在的 `apkanalyzer_path`；状态为 VERIFIER_UNAVAILABLE，不分发。
- [ ] 设置 `verification_enabled=false` 与 `auto_flash_transfer=true`；显示
  CONFIG_SECURITY_ERROR，不分发。
- [ ] v0.3.0 旧 `downloads/arcaea_*.apk` 保留但不自动 VERIFIED。
- [ ] 同一失败 APK 的 scheduler 安全通知不会每轮刷屏。
- [ ] 验证失败 APK 从未出现在任何 QQ 闪传消息中，也没有普通群文件回退。
