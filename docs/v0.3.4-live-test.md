# v0.3.4 APK 保留数量与自动清理实机验证

本版修复旧清理逻辑只覆盖 pending、从未清理 verified 的问题，并将开启保留时的
无限归档改为滑条限额。以下项目需在部署机器验证；本地合成文件测试不代表实机通过。

## 升级与配置

- [ ] 备份 `state.json` 和需要长期保存的 APK；清理会实际删除超额的受管理旧包。
- [ ] 安装 v0.3.4，保留原 signer、package、Build Tools、白名单与分发配置。
- [ ] WebUI 显示“保留旧版本 APK”及“保留的旧版本 APK 数量”滑条：0–20，默认 1。
- [ ] `/apull status` 显示 v0.3.4 和实际生效的 `old_versions_to_keep`。

## 已有 verified 包清理

- [ ] 当前 verified APK 的路径、大小、SHA-256 和信任配置正常。
- [ ] 开启保留，将数量设为 2，保存配置并重载插件。
- [ ] verified 中仅留下当前可信 APK 和最近 2 个旧包（原包数不足时不补齐）。
- [ ] 将数量改为 1，再次重载；仅留下当前可信 APK 和最近 1 个旧包。
- [ ] 将数量改为 0，或关闭保留；只留下当前可信 APK。
- [ ] 不启用定时检查、自动下载时，重载仍能清理已有 verified 历史包。
- [ ] `/apull verify` 复用当前已验证 APK 时也会应用上限，无需重新下载。

## 安全与回归

- [ ] 新版下载成功但验证失败时，旧 verified 包不会被这次验证清理。
- [ ] 当前包缺失、被篡改、信任配置为空或工具不可用时，重载不会触发 verified 清理。
- [ ] downloads 根目录的 legacy APK、quarantine、`.part`、其他文件及目录保持完整。
- [ ] 旧文件被占用或无删除权限时，日志给出警告；当前包验证仍成功，解除占用后重试清理。
- [ ] 已删除文件不再出现在 verification.artifacts 中；完整 versionCode 高水位未重置。
- [ ] distribution 历史仍在；对已分发的当前版本再次 `/apull distribute` 显示 skipped。
- [ ] 同目录有多份 pending 时，下载成功或复用当前 pending 后按同一上限清理。
