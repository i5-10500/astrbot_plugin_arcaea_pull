# v0.3.0 QQ 闪传自动分发实机验证清单

本清单用于发布前验证自动分发。单元测试只验证状态机和 OneBot action 载荷，不能
替代真实 AstrBot、NapCat、QQ 服务端及客户端测试。

## 测试基线

- 插件：v0.3.0 安装 ZIP
- NapCat：v4.10.47 或更新版本
- AstrBot：记录实测版本和 aiocqhttp 平台 ID
- 机器人 QQ、目标群号、测试端 QQ 客户端版本：记录但不要提交敏感凭据
- AstrBot 兼容性源码快照：`AstrBotDevs/AstrBot@5152c09a789dd6db7ab8ac10c0e05e7ad7e0b007`
  - `Context.platform_manager`：`astrbot/core/star/context.py`

    `astrbot/core/platform/sources/aiocqhttp/aiocqhttp_platform_adapter.py`

## 准备

- [ ] 备份插件的 `state.json`，确认磁盘有足够空间。
- [ ] 只把专用测试群加入 `flash_transfer_targets`。
- [ ] 先关闭 `auto_flash_transfer`，执行 `/apull flash_test`，确认小文件是 QQ 闪传。
- [ ] 多 aiocqhttp 实例时设置 `flash_transfer_platform_id` 或
  `flash_transfer_self_id`；确认 `/apull status` 不显示歧义。
- [ ] 启用 `auto_download=true` 和 `auto_flash_transfer=true`。

## 自动与手动路径

- [ ] `/apull check` 下载当前 APK，并向每个白名单群各闪传一次。
- [ ] 再次 `/apull check`，版本不变时成功目标显示 skipped，群内没有重复 APK。
- [ ] `/apull distribute` 对成功目标同样跳过，不触发下载。
- [ ] 临时阻断一个目标或停用 NapCat，触发一次失败；恢复后版本不变再次检查，
  失败目标重试成功，原成功目标不重发。
- [ ] 新增一个测试群到白名单；下次检查只发送新增群。
- [ ] 从白名单移除一个群；后续检查不再处理该群，历史状态仍保留。
- [ ] 重载 aiocqhttp 适配器后再次分发，确认使用新活动客户端成功发送。
- [ ] 定时检查触发的结果与手动 `/apull check` 一致。

## 失败关闭与可观察性

- [ ] 设置 `auto_flash_transfer=true`、`auto_download=false`，状态明确显示
  `AUTO_FLASH_MISCONFIGURED`，没有下载和分发。
- [ ] 配置两个活动 aiocqhttp 实例且不设置选择器，状态显示歧义且不发送。
- [ ] `/apull distribute` 在当前远端版本没有可靠本地 APK 时拒绝，且不产生下载。
- [ ] 非白名单群执行 `/apull flash_test` 被拒绝；没有普通群文件回退消息。
- [ ] `/apull status` 显示当前版本的 pending/success/failed 数量。
- [ ] 成功与失败通知只发送到 `notify_targets`，APK 只发送到
  `flash_transfer_targets`。
